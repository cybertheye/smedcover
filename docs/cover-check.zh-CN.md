# 方案：平台封面尺寸、封面体检、两种界面

状态（2026-10-20）：专业版的体检和一键修正做过后取消了——停手后要在后台把每个尺寸重画一遍，编辑时明显卡顿。第 2 节的标准改为直接写进版式：`layout.js` 的 `meetStandards()` 让每种风格的版式都按这些标准排（不压角标、标题留够字号、频道图形够大），新封面自带角标 `EP.01`；`check.js` 留作这些规则的纯函数，测试用它检查版式。小白版待做。

SmedCover 给小白用，目标是**交付能用的结果**。这份方案包括三部分：

1. **平台封面尺寸**：6 个平台各要哪些封面、多大。
2. **封面体检**：用什么标准判断一张封面合不合格，一键修正怎么改。
3. **两种界面**：现在的界面改叫「专业版」，体检和一键修正放在这里；另做一个「小白版」，选平台、写标题、放垫图，直接按体检标准生成。

两种界面用**同一套体检引擎**：专业版里它是「检查 + 一键修正」，小白版里它在生成时自动跑，直接交出合格的封面。

## 1. 平台封面尺寸

### 1.1 各平台要的封面（真机核实，2026-10-19）

比例是在真机上传页核实过的；像素是推荐的导出尺寸。

| 平台 | 要的封面 | 推荐导出尺寸 |
|---|---|---|
| B站 | 16:9 和 4:3，两张都要 | 1920×1080；1440×1080 |
| YouTube | 横版视频：16:9；竖版视频：9:16 | 1280×720（宽至少 640，文件不超过 2MB）；1080×1920 |
| 抖音 | 4:3 和 3:4，两张都要 | 1440×1080；1080×1440 |
| 小红书 | 4:3、3:4、1:1 任选一种（和视频比例无关） | 默认 3:4，1080×1440；也可 1440×1080 或 1080×1080 |
| 视频号 | 竖版视频：3:4；横版视频：3:4 和 4:3 | 1080×1440；1440×1080 |
| 公众号 | 2.35:1 和 1:1，两张都要 | 900×383；900×900 |

所以体检和小白版除了「发哪些平台」，还要知道两件事：

- **视频是横版还是竖版**：决定 YouTube 和视频号要哪些封面。
- **小红书用哪个比例**：默认 3:4。

### 1.2 合在一起要导出的尺寸

6 个平台全选、横版视频、小红书用 3:4 时，要排版的比例有 5 种（16:9、4:3、3:4、2.35:1、1:1）：

| 比例 | 导出像素 | 给谁用 |
|---|---|---|
| 16:9 | 1920×1080 | B站 |
| 16:9 | 1280×720 | YouTube（横版视频） |
| 4:3 | 1440×1080 | B站、抖音、视频号（横版视频） |
| 3:4 | 1080×1440 | 抖音、小红书、视频号 |
| 2.35:1 | 900×383 | 公众号 |
| 1:1 | 900×900 | 公众号 |

竖版视频时，YouTube 换成 9:16（1080×1920），视频号只要 3:4。同一比例只排一次版，不同像素只是导出时缩放。

**和上一版方案相比**：B站的 4:3 从「可选」变成「必做」；抖音不再要 9:16，改成 4:3 和 3:4；视频号不是 6:7，而是 3:4（横版视频再加 4:3）；YouTube 竖版视频要 9:16。各平台都是单独上传每种比例的封面，所以第 2 节的「被平台裁掉」（D2）这一期不需要了。

### 1.3 信息流里显示多大（体检要用）

体检要知道封面在手机信息流里**实际显示多大**。下面是按常见手机屏宽（约 390pt）估的，**全部要实测**：

| 位置 | 封面显示宽度（估计） |
|---|---|
| B站首页双列 | 约 175px |
| YouTube 首页单列 | 约 390px（推荐侧栏小图约 168px） |
| 小红书双列瀑布流 | 约 185px |
| 抖音主页三列网格 | 约 128px（最小） |
| 视频号 | 待测 |
| 公众号消息列表头条 | 约 360px；次条小方图约 60px |

## 2. 封面体检：检测标准与一键修正

### 2.1 总原则

- 每条检查都写明**检测标准**和**依据**。有公认标准的用公认标准（比如对比度用 WCAG）；没有的，是我们定的起始值，**要用真实封面校准**（见 2.4）。
- 「关键内容」指：**标题**、**主体**（抠出的人物、铺满的照片里的人、频道图形）、**用户加的文字**。品牌行、角标、频道名算次要内容。
- 每个尺寸单独检查。一个尺寸可能同时对应多个平台（3:4 同时给小红书和抖音），按其中最严的标准算。
- 一键修正是**按顺序尝试的一串动作**：做一步，重新检查，通过就停；全试完还不通过，就保留问题，告诉用户需要手动改哪里。每次修正是一步撤销，只改出问题的尺寸。

### 2.2 检查项、标准和修正

#### A1 标题在信息流里看不看得清（红 / 黄）

- **检测**：取标题实际排出的字号（虚拟画布上的像素），按该尺寸在平台信息流里的显示宽度换算成屏幕像素：`屏幕字号 = 字号 × 显示宽度 ÷ 画布宽度`。
- **标准**：不小于 14px 通过；10～14px 黄；小于 10px 红。
- **依据**：手机界面正文的最小字号一般是 11～12pt；封面是一扫而过的，所以定得更严。没有行业公认的封面字号标准，**这是起始值**。
- **修正顺序**：
  1. 在这个尺寸放大标题，不超出画面安全区。
  2. 换成这个比例下标题区更大的版式。
  3. 还不够：告诉用户「标题太长，在抖音主页看不清，建议缩短到 N 个字」。N 按当前大小反算。

#### A2 标题字数和行数（黄，只提示）

- **检测**：数字数（不算 `*`）和行数。
- **标准**：最多 2 行，每行最多 10 个字。
- **依据**：经验规则。字越多，同样的标题框里字越小，最终还是 A1 的问题。
- **修正**：无。文案是用户的，只提示「一行 3～8 个字最好」。

#### B1 标题和背景的对比（红 / 黄）

- **检测**：把标题下面的图层单独画一张小图，在标题文字覆盖的区域取背景亮度；用文字颜色（有描边或底牌时，用描边或底牌的颜色）和背景算对比度。背景花的时候取**最差的 10%** 区域，不取平均值。
- **标准**：对比度不低于 3:1 通过；2:1～3:1 黄；低于 2:1 红。
- **依据**：WCAG 2.x 的 1.4.3 条：大字号文字（18pt，或 14pt 粗体以上）的最低对比度是 3:1。封面标题都是大号粗体，适用这条。红线 2:1 是我们定的。
- **修正顺序**：
  1. 加粗描边（当前文字效果画描边时）。
  2. 压暗背景照片，每次加 0.15，最多到 0.5（先于底牌：底牌对画面改动更大）。
  3. 加底牌。
  4. 文字换成黑或白里对比更强的那个。

#### C1 主体够不够大（黄）

- **检测**：除文字外最大的元素（抠出的人物、照片、频道图形、贴纸）占画面的比例。
- **标准**：不小于 12% 通过，小于 12% 黄。
- **依据**：经验规则，**起始值**。第二期改成用 macOS Vision 检测人脸，按「人脸占画面多少」判断。
- **修正顺序**：
  1. 在这个尺寸放大该元素，不超出画面。
  2. 照片里有人物但还没抠图时，提示「抠出主体」。

#### D1 关键内容被平台角标挡住（红 / 黄）

- **检测**：关键内容的框（来自画布的命中记录，即每个图层画出来的位置）和平台遮挡区（比如 B站右下角的时长）求交。
- **标准**：没有交叠通过；有交叠黄；被挡超过自身面积 15% 红。
- **依据**：遮挡区来自平台实测；15% 是我们定的。
- **修正**：在这个尺寸把图层挪出遮挡区，取最短的移动距离，并保证挪完不出画面、不撞进别的遮挡区。

#### D2 关键内容被平台裁掉（红 / 黄）

- **检测**：同 D1，和裁切框外面的区域求交。按 1.1 的真机结果，各平台都单独上传每种比例的封面，**这一期没有需要检查的裁切**；平台以后开始裁切时，只需在 `platforms.js` 里加裁切框。
- **标准**：标题被裁红；主体被裁黄。
- **修正**：同 D1，往裁切框里挪。

#### E1 缺少平台要的尺寸（红）

- **检测**：选了某平台，档案里没有它必做的封面尺寸（见 1.1）。
- **修正**：添加该尺寸。

#### E2 文件超过平台上限（黄，导出时检查）

- **检测**：导出后的文件大小和平台上限比较（YouTube 2MB）。
- **修正**：改用 JPEG，逐步降低质量直到满足。

### 2.3 严重程度

- **红（问题）**：很可能看不清、被挡住、被裁掉。
- **黄（建议）**：改了更好。
- 不打总分。

### 2.4 阈值校准

每个平台找 20～30 张表现好的真实封面，用体检跑一遍，应当基本都通过。据此调整 A1、C1、D1 的起始值。

## 3. 两种界面

### 3.1 专业版（现在的界面）

现在的界面不变，加上体检：

- 顶栏「导出」旁边有个体检徽章：绿色「体检通过」、黄色「2 条建议」、红色「1 个问题」。停手约半秒后自动重算，拖动中不算。
- 点徽章打开体检面板：
  - **问题清单**：每条用大白话写问题，点一下在画布上框出位置并选中图层，有「一键修正」和「忽略」。
  - **平台预览**：按平台切换，按信息流里的实际大小显示封面，叠上时长角标和裁切框（第二期）。
- 画布上可以打开「显示平台遮挡区」，用半透明色块标出各平台会被挡住、会被裁掉的地方。
- 导出对话框顶部显示体检摘要；有红色问题时提醒一句，不拦着导出。

### 3.2 小白版（新界面）

只有左右两栏。

**左栏：填三样东西**

1. **发到哪**：平台多选按钮（B站、小红书、抖音、YouTube、公众号、视频号），默认记住上次选的。下面一个开关「视频是：横版 / 竖版」（决定 YouTube 和视频号要哪些封面）；选了小红书时，多一个「小红书比例：3:4 / 4:3 / 1:1」。
2. **标题**：一个输入框，下面写着「一行 3～8 个字最好，用 *星号* 标出重点词」；超过建议长度时提示是哪个平台会看不清。
3. **垫图**：上传、拖进来、从图库选。可以不放，用风格自带的背景。照片里有人物时，有个开关「人物突出」（默认开），把人物抠出来压在标题上。抠图只在桌面应用里能用。
4. **风格**：一排风格缩略图，用的就是你自己的标题和垫图，点哪个换哪个；还有「换一个」，随机换风格和配色。
5. 底部一个大按钮：**导出全部（N 张）**。按平台分文件夹导出，文件名带平台和尺寸，格式和大小自动满足平台要求。

**右栏：预览**

- 每个平台一张卡片，按选的平台排列，标着平台名和尺寸。
- 卡片角上一个小标记：绿色表示合格；黄色表示自动修正后仍有建议，点开看是什么（比如标题太长）。
- 点卡片放大看。第二期可以切换「在信息流里看」。

**品牌和频道**：小白版用当前档案的品牌名和频道配色，不出现在界面上。档案有多个频道时，左栏顶部多一个频道下拉框。

**和专业版的关系**

- 两个界面编辑的是**同一份数据**：小白版改的标题、垫图、风格、平台，就是专业版里的标题、照片图层、风格、尺寸。
- 顶栏一个切换：`快速出图 | 专业版`。新用户默认进小白版。
- 小白版里点「去专业版细调」，进入专业版，停在当前封面。在专业版加的图层、做的调整，回到小白版时预览里照样显示，只是小白版没有调它们的控件。

### 3.3 小白版的生成流程

每次输入变化（标题、垫图、风格、平台），停手后按下面的顺序生成：

1. **定尺寸**：按选的平台得出要排版的比例（见 1.2）。
2. **定版式**：按比例选模板。宽的（2.35:1）用横幅；竖的（3:4、9:16）用上下排列；16:9 和 4:3 用当前风格默认的模板。
3. **放图**：垫图铺满画面；「人物突出」开着、而且检测到人物时，抠出人物放在标题上方。
4. **放标题**：照现有的标题排版，自动适配字号。
5. **跑体检，自动修正**：A1、B1、C1、D1 都按第 2 节的修正顺序自动执行，直到通过或试完。
6. **出结果**：全部通过的显示绿色；修不好的显示黄色，并说明原因和建议（大多是「标题太长」）。

生成只改「仅此尺寸」的微调，所以切到专业版看到的是同一份结果，可以接着手动改。

## 4. 技术实现

- **`ui/js/platforms.js`**：平台规格数据，包括各封面的比例、导出像素、是否必做、信息流显示宽度、遮挡区和裁切框（比例坐标）、文件上限、核实日期。
- **`ui/js/check.js`**：体检，纯函数，可在 Node 里单测。输入每个尺寸的排版结果（图层的框，即 `cv._hits`；标题的字号、行数、字数、文字和描边颜色；背景亮度采样）和平台规格；输出问题列表：`{id, level, platform, size, layerId, rect, fixes}`。
- **`ui/js/fixes.js`**：一键修正，每个修正是一个函数，改数据后重新体检；专业版手动点，小白版自动跑。
- **`render.js`**：加一个只画某一层下面那些图层的选项（`o.below`），给 B1 采样标题背后的背景；标题自己用 `o.only` 单独画。字号从标题的命中框和行数反算，不用另外导出。
- **何时计算**：每个需要的比例画三张约 320px 宽的小图（整张、只有标题、标题下面的图层）。停手 1.5 秒后在后台逐个尺寸算，拖动中不算；打开体检时立刻算。
- **小白版界面**：`app.js` 里新增一种模式，和现在的「编辑」「配置」并列，自己的左右两栏；右栏预览复用缩略图的绘制。

## 5. 分期

1. **平台规格实测**：6 个平台真机核实，写进 `platforms.js`；尺寸预设按 1.2 更新。
2. **体检引擎**：`platforms.js` 和 `check.js`（修正在 `app.js` 里），第一批检查 A1、A2、B1、C1、D1、E1，带单元测试。**已完成。**
3. **小白版界面**：左右两栏、自动生成、导出全部。
4. **专业版的体检**：徽章、问题清单、一键修正。做完后**已取消**（编辑时卡顿），标准改由版式自己遵守（`meetStandards()`）。
5. **第二期**：平台信息流预览、导出文件大小检查（E2）、用 Vision 检测人脸。
6. **以后**：根据视频内容建议标题文案；同一频道的系列感检查。

先做小白版（第 3 步），再做专业版的体检（第 4 步），因为小白版是新用户的主路径，而且两者共用引擎，引擎在第 2 步就绪。

## 6. 验收标准

- 默认版式在每种风格、每个尺寸下都合乎 A1、C1、D1（单元测试覆盖）。
- 故意做坏的封面能查出对应问题：标题很小、压在花哨照片上、放在 B站右下角，应当分别报 A1、B1、D1。
- 每个一键修正之后，对应问题消失；撤销一次回到修正前。
- 小白版：选全部 6 个平台、写一个 6 字标题、放一张人像照片，生成的 9 张封面全部是绿色。
- 停手后体检在 50ms 内出结果，拖动时不算、不卡。

## 7. 待定问题

1. **界面名字**：「小白版」对用户来说可能有点居高临下，界面上建议叫「快速出图」，专业版叫「专业版」。
2. **小白版的标题**：只有主标题，还是加一个可选的副标题或角标（比如「EP.03」）？
3. **平台规格**：各平台要的比例已真机核实（见 1.1）；还要实测的是 1.3 的信息流显示宽度、各平台角标（时长等）的位置和大小，以及文件大小上限。
4. **阈值**：A1 的 14px / 10px、C1 的 12%、D1 的 15% 都是起始值，要校准。
